# AGENTS.md — Қақпан (Qaqpan)

**Этот файл обязателен для любого участника команды и любого агента, который работает над проектом. Прочитать целиком до первого действия.**

## 0. North star — не терять суть проекта

Қақпан — адаптивная система защиты клиентов банка от социальной инженерии и телефонного мошенничества. Защита работает в момент перевода: спокойные операции проходят мгновенно, подозрительные проверяются вопросом, самые опасные отправляются доверенному лицу. Рядом работает «мошенник-робот», который ищет дыры в защите и доказывает её эффективность цифрами.

- Папка проекта: `Qaqpan/`
- Бэкенд: `backend/` — Python, FastAPI, SQLite
- Фронтенд: `frontend/` — React (Vite), Tailwind CSS
- Платформа: хакатон Банка ЦентрКредит, веб-приложение, демо перед жюри
- Статус: Phase 0 — документы готовы. Код не начат. Следующий шаг — Phase 1.

## 3. Работа с Git: прямо в `main`

Все работают в ветке `main` без создания отдельных веток.

**Правило «1 человек = свои файлы»:** каждый редактирует только файлы из своей колонки в таблице выше. Это исключает merge-конфликты.

**Единая команда перед каждым push:**
```bash
git pull --rebase origin main && git push origin main
```

**Запрещено:**
- Редактировать чужие файлы без явного согласования с владельцем.
- Пушить код, который ломает `uvicorn` / `npm run dev`.
- Коммитить напрямую в `main` файлы с синтаксическими ошибками.

## 4. Жёсткие продуктовые ограничения

Это не рекомендации. Нарушение = провал демо или потеря доверия жюри.

### Демо и первый экран
- Демо длится **3 минуты**. Каждая секунда на счету. Никаких загрузок, ошибок и «подождите» на сцене.
- Три экрана должны синхронизироваться в реальном времени: действие бабушки мгновенно видно у дочери и аналитика.
- Система должна работать **с интернетом и без** (fallback на локальный regex-парсер).

### Автомат состояний (FSM)
- Каждый перевод проходит через конечный набор состояний. Невалидные переходы запрещены на уровне кода.
- Сценарий «близкий не отвечает» обязателен: тайм-аут → период охлаждения → клиент может отменить сам.
- Клиент может отменить перевод **в любой момент** до исполнения. Деньги не блокируются навсегда.

### ИИ и правила
- Решение о риске принимают **прозрачные правила с порогами**, а не «чёрный ящик» LLM.
- LLM только разбирает текст ответа клиента на признаки. Каждое решение объяснимо.
- JSON Schema на выходе LLM обязательна. Свободный текст от модели не принимается.
- При сбое LLM (таймаут >1.5с, отсутствие сети, невалидный JSON) мгновенно срабатывает локальный regex/keyword парсер.

### Мошенник-робот
- Синтетические сценарии делятся на **train и test**. Правила настраиваются на train, проверяются на test.
- Обязательно сравнение с Baseline: «только лимит суммы > 500k ₸» vs «лестница Қақпан».
- Метрики: Stop Rate, False Positive Rate, доля законных переводов с вопросом, средняя задержка.

### Честные ограничения (написать на слайдах)
- Работаем на учебной модели и синтетике.
- Готовность к внедрению не заявляем.
- Не обещаем, что ИИ распознает мошенничество. Показываем, что многоуровневая защита снижает пропуски без большого числа ложных задержек.

## 5. Правила кода

### Бэкенд (Python)
- Python 3.10+. Type hints обязательны. `Any` — только с комментарием.
- Все модели — Pydantic v2 с жёсткой валидацией.
- FSM — явный enum состояний с whitelist допустимых переходов. Невалидный переход = исключение.
- Эндпоинты возвращают Pydantic-модели, не `dict`.
- Никаких `print` в production. Использовать `logging`.
- Секреты (API-ключи LLM) — через `.env`, не хардкодить. `.env` в `.gitignore`.
- Каждый API-контракт сначала описывается в `models/schemas.py`, потом реализуется.

### Фронтенд (React)
- TypeScript strict. `any` — только с комментарием.
- Компонент = один файл. Не смешивать логику трёх экранов в одном компоненте.
- SSE/polling для синхронизации — через единый хук/сервис, не дублировать в каждом экране.
- Все тексты — в отдельном файле/объекте для RU и KZ. Никакого хардкода строк в JSX.
- Адаптив: мобильный вид для Клиента и Доверенного лица, десктоп для Аналитика.

### Общие
- Один коммит — одна задача. Не рефакторить чужой модуль «попутно».
- Комментарии в коде — на английском. Документация, README, промпты — на русском.
- Не добавлять зависимости без согласования с командой.

## 6. Обязательные проверки после каждого шага

1. Бэкенд запускается: `uvicorn backend.app.main:app --reload` без ошибок.
2. Фронтенд собирается: `npm run dev` в `frontend/` без ошибок.
3. API отвечает на тестовые запросы (curl или Swagger UI).
4. Три экрана (Клиент, Доверенное лицо, Аналитик) открываются без ошибок в консоли.
5. Если менялся FSM — прогнать все 5 веток: LOW → COMPLETED, MEDIUM → ANSWER → COMPLETED, MEDIUM → ANSWER → TRUSTED, TRUSTED → DECLINE, TRUSTED → TIMEOUT → COOLING.
6. Если менялся AI-парсер — прогнать 10 тестовых фраз на RU и KZ.
7. Если менялся бенчмарк — проверить сходимость метрик на train и test наборах.

## 7. Definition of Done для шага

Шаг считается законченным, только если:

- фича работает при запуске бэкенда и фронтенда;
- нет новых ошибок в консоли браузера и терминале;
- API возвращает ожидаемые JSON-ответы;
- если затронут FSM — проверены все ветки переходов;
- если затронут парсер — протестированы RU и KZ фразы;
- если затронут UI — проверены мобильный и десктоп вид;
- обновлён `ROADMAP.md` (чекбокс шага).
